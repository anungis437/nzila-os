## Usage Constraints

Prohibited ambiguous use: do not use “canonical,” “standard,” “validated,” “reference implementation,” “institutional graph,” or “digital twin” as a product description or external claim without the distinct evidence and governance state required by the qualification program.

## Wave 2B Candidate Reconciliation

| Term group | Candidate treatment | Resolution status |
| --- | --- | --- |
| Institution, organization, mandate, capability | Retain I.1 definitions and I.2 architecture use; do not equate organization with institution outside the candidate scope. | External disciplinary review required. |
| Evidence, knowledge, memory, stewardship, continuity, legitimacy, modernization | Retain proposed authority; preserve existing Nzila terminology and methods unchanged. | Collision review remains open. |
| Architecture, system, engineering, science | Use as descriptive candidate-corpus terms only; no professional, standards, or scientific-status assertion. | External foundations review required. |
| Reference architecture, exemplar, reference implementation | Treat exemplar as non-qualified descriptive language; reserve reference architecture and implementation labels for separately evidenced qualification. | Definition review and reference-case evidence required. |
| Institutional graph, digital twin, validation, canonical, normative | Candidate I.2 notice prevents modal wording from being read as normative. I.3 terms remain conceptual and unimplemented. | Specialist technical review required. |

No established Nzila term is changed, reclassified, or adopted through this reconciliation.
