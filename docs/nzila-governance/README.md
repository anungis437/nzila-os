# Nzila Institutional Doctrine — Operational Governance Layer

This directory binds the doctrine corpus under [../nzila-ip/](../nzila-ip/) into **enforceable organizational governance infrastructure**. It is the operational counterpart to the IP layer: where the IP layer states what Nzila believes, this layer ensures Nzila *acts on those beliefs in every system, decision, and release*.

## What lives here

- **Traceability** — explicit mapping from doctrine principles to product/system behavior
- **Review frameworks** — standardized procedures for evaluating new work against doctrine
- **Design and architectural governance** — UX and architecture standards derived from doctrine
- **Executable enforcement** — code review, CI/CD, E2E, routing, and gating bindings
- **Domain governance** — AI, executive cognitive, deployment, narrative, expansion
- **Measurement** — scorecards and readiness reviews

## What does NOT live here

- New doctrine (lives in [../nzila-ip/](../nzila-ip/))
- Product specifications, schemas, infrastructure
- Marketing copy or sales material
- Engineering implementation code

## Governing principle

> Doctrine is executable governance, not optional philosophy. Every future feature, flow, dashboard, routing rule, AI capability, deployment decision, UX pattern, and modernization decision is reviewable — and gated — against the doctrine corpus.

Drift without detection is the failure mode this layer exists to prevent.
