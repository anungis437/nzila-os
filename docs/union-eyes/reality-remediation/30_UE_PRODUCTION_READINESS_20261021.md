## What this increment changed

Scoped migration `0019_deadline_reassignment_convergence` creates `deadline_reassignment_convergence` when absent and, when root `migrations/0049_union_eyes_deadline_convergence_tasks.sql` already created it, drops that migration's PUBLIC policy. The replacement is `ue_create_direct_org_rls_policy` (FORCE RLS, no empty-context fallback). `union_eyes_runtime` receives `SELECT` and `INSERT` (the assign route inserts with `RETURNING`). `union_eyes_system` receives `SELECT` and `UPDATE` (the post-commit retry and the reminder cron). Runtime `UPDATE` and system `INSERT` are not granted. Before any policy or grant change, the migration requires the thirteen-column physical contract, the primary key on `id`, the status check, the named terminal check, and both index definitions. An event trigger then rejects a later `CREATE POLICY` or `ALTER POLICY` that would put the 0049 PUBLIC fallback, or any other unapproved policy, back on this table. Supported bootstrap and deploy appliers do not execute `0049`.

`0019` is source-tested on PGlite. The same scenarios passed on disposable local PostgreSQL 15.19 and 16.15: fresh apply, a database that already had root `0049`, a second apply, a partial upgrade that leaves one table, an interrupted transaction that rolls back, and deliberate drift of the primary key, terminal check, nullability, extra column, status default, identifier length, and pending index. Tenant A, tenant B, an empty organization context, a forged insert, a runtime update, a system insert, an unauthorized role, and a system-only update were included. Replaying `0049` after the closure was rejected and the approved policies remained. That is engine proof. It has not been applied to staging. `CHG-2026-0112` stays `PROPOSED`. No Azure resource was changed.
