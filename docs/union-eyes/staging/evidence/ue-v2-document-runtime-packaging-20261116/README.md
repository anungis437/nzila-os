# PDF/OCR runtime packaging repair

A cached Linux image failed to load the installed PDF library because standalone tracing omitted its native canvas dependency (`DOMMatrix is not defined`). Docker, Next.js configuration, application dependencies and lockfile were byte-identical at that image source and admitted privacy source 232bfa049. The builder now copies the installed PDF/OCR dependency graph with its actual nested package paths, hashes the copied inputs and verifies native PDF imports plus OCR worker/WASM files. Missing required dependencies and packages outside the installed boundary fail the build.

The [Linux rehearsal](linux-rehearsal.json) used the real copier output and a lock-integrity-verified Linux native package on the prior Linux base, with network disabled and a seeded synthetic OCR model. PDF text extraction, real image OCR and mixed-page rendering/OCR passed. It did not run the new candidate image, product service or HTTP routes, and does not qualify first-use model download.
