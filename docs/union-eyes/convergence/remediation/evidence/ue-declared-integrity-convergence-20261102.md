# Convergence tranche 7: the declared integrity classes close (indexes, foreign keys, checks, NOT NULL, time zones)

Date: 2026-11-02. Branch `agents/ue-cursor-final-closure`. Base commit `bf62586b8` (tranche 6 ledger). Platform migrations `0066_declared_indexes`, `0067_declared_checks`,
`0068_declared_foreign_keys`, `0069_declared_not_null`.
Credit: none for the tranche itself (cross-cutting source evidence, `defectCredit` 0, `closureCredit` 0). Nothing is closed. `READY_FOR_STAGING` stays `NO`.
This tranche acts on the direction "address all the missing tables, columns, etc.; fix everything, even if it was you who built it first": tranche 6 closed the classes that make a
statement fail; this one closes the classes that make a declared guarantee false.

## What was wrong

Tranche 6 pinned five advisory classes as measured, not closed: 370 foreign keys, 794 indexes, 286 declared NOT NULL, 420 `timestamp` declarations over `timestamptz` columns and 36 checks.
The measurement itself was blind in places: it skipped every partial, expression and non-btree index, looked at only the first declaration of a column when it compared a time zone,
kept no constraint names, and could not tell a constraint that exists from one PostgreSQL has not validated.

## What the measurement learned (`scripts/runtime/schema-convergence.ts`)

- It keeps the full declaration of every index (name, method, per-column order, nulls and operator class, expression, predicate, storage options), every foreign key (name, actions) and every check
  (name and expression with bare column names), and compares an index by structure when it is plain and by name when it is not.
- It compares the time zone of every declaration of a column, not just the first, and measures a new class, `CONSTRAINT_NOT_VALIDATED`, for a foreign key or check that exists but was never validated.
- An index over a column that only exists where an extension is installed follows the column (`EXTENSION_ABSENT` reports it).
- On the converged database of tranche 6 it measures 370 foreign keys, 798 indexes, 286 NOT NULL, 423 time zones and 36 checks: the larger counts are the declarations the old measure never looked at.

## What changed

**Declarations (no migration).**

- **Time zones.** `scripts/codemods/declare-timestamptz.cjs` (a TypeScript-syntax-tree codemod, so it changes the `timestamp(...)` call and nothing around it) declares `withTimezone: true` on 685 declarations in
  74 files, for the 423 (table, column) pairs whose physical column is `timestamp with time zone`. The type stays `Date`. What changes is how a value is read: a declaration without the zone parses
  `2026-11-01 18:51:12-05` as if it were UTC, so every read was wrong by the session's offset unless the session ran at `+00`. A flat declaration file and its `domains/` twin are both changed.
- **A declaration that said less than the database.** `deadline_reassignment_convergence_pending_idx` is declared total and exists partial (`WHERE status = 'pending'`, scoped 0019); the declaration now states the partial index.
- **A name two declarations gave to different indexes.** `reward_wallet_ledger_org_user_idx` is declared over `(org_id, user_id)` and exists over `(org_id)` (the Django model named its own index the same); the declarations are renamed
  `reward_wallet_ledger_org_user_id_idx`, so the composite index is created beside it instead of being skipped by name.
- **A check that refuses real addresses.** `user_management.users.valid_email` rejected `+` and every non-ASCII character; it now requires one `@`, no spaces and a dot in the domain.
- **The foreign-key doctrine** (below): 77 declared foreign keys removed (135 declarations across twins).

**Migrations.** All four are generated by `scripts/generate-declared-convergence.ts` from the register in `evidence/ue-declared-integrity-input-20261102.json`, guarded, tagged and reversible, and apply on fresh PG15 and PG16.

| migration | what | fail-closed on |
|---|---|---|
| `0066_declared_indexes` | 797 indexes (3 unique, 2 partial) created where no index of that name exists | a name another relation holds; duplicate rows under a unique index |
| `0067_declared_checks` | 36 checks, added `NOT VALID` then validated | a row that violates one |
| `0068_declared_foreign_keys` | 293 foreign keys (193 cascade, 42 set null, 13 restrict, 45 no action), added `NOT VALID` then validated | an orphan row |
| `0069_declared_not_null` | 157 declared NOT NULL columns (55 of them tenant keys) | a column that holds NULL |

Every index, check and foreign key a migration creates is tagged, so its rollback drops exactly those; the NOT NULL rollback relaxes exactly the listed columns. No policy, grant or row-security setting changes.

## The foreign-key doctrine

A declaration may not promise a foreign key the platform must not enforce (`foreignKeyDoctrineViolations`, pinned by the ratchet).

- **Identity strings are values, not keys.** The identity authority gives a signed-in principal a `profiles` row only when that user first opens the dashboard: `app/[locale]/dashboard/layout.tsx` is the one place in the
  application that inserts a profile. `user_management.users` belongs to the retired credential schema. An administrator acting through the API, a mobile device, a SCIM-provisioned person or a system job has a valid identity and no
  such row, so a `created_by`, `user_id` or `member_id` that references `profiles.user_id` or `users.user_id` would refuse the write. 67 declared references of that kind are removed (56 to `profiles.user_id`, 11 to `users.user_id`).
  Thirty such keys were created by the legacy migrations and are enforced today; removing an enforced key is a separate decision, so they stay declared and measured (`GRANDFATHERED_IDENTITY_REFERENCES`)
  until the identity authority provisions a profile for every principal and the rest can follow.
- **Evidence carries identifiers, not keys.** An append-only audit or security record outlives the rows it describes and records principals that may not exist (a failed sign-in, a system actor); a cascade from its parent would
  destroy it. The eight evidence tables (`audit_security.audit_logs`, `audit_security.security_events`, `financial_audit_log`, `signature_audit_log`, `signature_audit_trail`, `cross_org_access_log`,
  `user_management.auth_audit_log`, `data_anonymization_log`) carry no declared foreign key; ten more declarations are removed on them.

## The NOT NULL rule

The database may not be stricter than the loosest legitimate writer. Of the 286 declared NOT NULL columns the database left nullable, 278 are `null=True` placeholders in the Django models (ported from the Drizzle declarations
as stubs). Applying all 286 broke the first whole native run in ten files: fixtures and, more importantly, the Django API, where a `GrievancesViewSet(ModelViewSet)` with `IsAuthenticated` may create a draft grievance with no number,
type, title or description. So `0069` applies a declared NOT NULL only where no live Django ViewSet can write the table (`scripts/runtime/django-writers.ts` reads `backend/<app>/views.py`: a ViewSet whose
`permission_classes` names `DenyAllPermission` is contained; any other ViewSet over the model is a writer):

- **157 applied** (149 on contained tables, 8 on tables with no ViewSet).
- **128 open**, on 105 tables a live Django ViewSet can write. They stay `NOT_NULL_ABSENT` until the Django model and API require them too; the ratchet holds the open set to exactly this rule, so containing a ViewSet later
  forces the constraint to be added.
- **1 open on purpose**: `payments.amount`. Platform 0015 added it nullable deliberately ("a payment recorded before the finance authority has no amount; the authority refuses to register it"), and the authority-kernel native
  test proves that behaviour. The declaration is what is wrong there. `NOT_NULL_DELIBERATELY_OPEN` names the reason, and the ratchet fails if an exception stops applying.

The first whole native run (PG16) with all 286 applied failed 10 files, 8 tests, 77 skipped behind failing `beforeAll`s. Each failure was a fixture shortcut or a real contract gap, and each was resolved on its merits:
`grievances` and `organization_members` rows inserted without the columns the Django API leaves optional (resolved by the rule above, not by loosening the fixture); a `congress_memberships` fixture that named a congress that
is not an organization (the congress is now inserted: the foreign key is right); a reversibility test whose proof about platform 0060 assumed no later migration had tightened a column (it now takes later migrations off first,
like its siblings).

## Found, not fixed here

- **The Django models.** 278 of the 286 NOT NULL targets are `null=True` in the Django models, and Django's migration state knows none of the 2,343 columns tranche 6 added. The Django models are ported stubs; they need to
  be regenerated from the database (fields, nullability, required API input) in one tranche, and the 128 open NOT NULL columns close with it.
- **Identity references.** The 30 grandfathered keys are enforced; the rest are by value. One policy for the whole platform needs a profile provisioned at the identity authority for every principal (not at a React layout).
- **Native route coverage.** The new keys, checks and NOT NULL columns are proven by the 592 native tests and by fresh builds; a route no native test reaches is not proven.
- **The 14 contested relations**, the pgvector readers, the 116 deny-all relations and the platform-economics routes (tranche 6 follow-ups) are unchanged.
- **The Gate 0 `.mjs` pin tests** (`ue-gate0-scope-lock`, `ue-gate0b3-classification`) fail on orphan ownership entries and tracked defects that no longer reproduce, take over thirty minutes locally and run in no
  workflow: the condition RUNTIME-ACCEPTANCE R-38 records. They are untouched by this tranche.

## What this does not do

It does not close any defect or reach CLOSED, and it makes no statement about staging or production. A constraint the database enforces is not a route that has been run as the real roles.

## Reproduce

```
# a database built the way the application builds it
Django migrate, then node tooling/scripts/run-union-eyes-drizzle-bootstrap.mjs
cd apps/union-eyes
DATABASE_URL=... npx tsx scripts/runtime/orm-physical-parity.ts --strict      # exits 1 when any strict class is present
DATABASE_URL=... npx tsx scripts/runtime/orm-physical-parity.ts               # every class, including the advisory ones
npx tsx scripts/codemods/drop-declared-references.ts                          # reports any declaration the doctrine forbids
```
