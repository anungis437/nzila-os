# CourtLens Public Intake UI — Phase 2F

## Status
- Phase 2A: public intake API implemented (`POST /api/courtlens/public-intake`).
- Phase 2B: tenant resolver added; API accepts `tenantSlug` (never raw `orgId`).
- Phase 2C.6: auth blockers closed (verified guards).
- Phase 2E.5: client mutation POSTs enforce Idempotency-Key.
- Phase 2F: **public intake UI implemented (this document)**.
- Phase 2G (demo smoke gate): not started.

## Route Added

- `/[locale]/courtlens/t/[tenantSlug]/intake` — public, unauthenticated.
- Registered in [apps/abr/proxy.ts](../../../apps/abr/proxy.ts) `isPublicRoute` matcher.
- Server-side pre-check: unknown or malformed `tenantSlug` renders a generic "intake unavailable" state (no existence leak).

## API Dependency

Single dependency: `POST /api/courtlens/public-intake` (Phase 2A + 2B).
- Route is already listed as public in `proxy.ts`.
- Route is already rate-limited and Idempotency-Key-enforced by the proxy.
- Route resolves `tenantSlug → orgId` server-side via `verifyAbrOrgMembership` chain (Phase 2B/2C.6 hardened).
- Route returns a safe confirmation only: `{ ok, matterId, practiceArea, statusLabel, submittedAt, legalBoundaryNotice }`.

## Public Request Shape (from the form)

Sent via `fetch('/api/courtlens/public-intake', { method: 'POST' })`:

```json
{
  "tenantSlug": "metro-university",
  "practiceArea": "housing" | "employment" | "debt",
  "subIssue": "eviction",
  "summary": "…at least 10 characters…",
  "consentAcknowledged": true,
  "riskFlags": { "risk_eviction": true },        // optional, keys validated server-side
  "hearingDate": "2026-08-01",                    // optional, ISO YYYY-MM-DD
  "deadlineDate": "2026-08-14",                   // optional
  "contactName": "Jane Smith",                    // optional
  "contactEmail": "jane@example.com",             // optional
  "householdSize": 3,                             // optional
  "hasChildren": true,                            // optional
  "hasDisability": false                          // optional
}
```

Headers on the fetch:
- `Content-Type: application/json`
- `Idempotency-Key: <uuid>` (generated by `createIdempotencyKey()` per submit)
- `credentials: 'same-origin'`
- **NOT sent**: `x-abr-role`, `x-org-id`, or any authorization header

## Confirmation Response Behavior

On `201`, the form renders only these fields (in a plain confirmation card):
- `matterId` (opaque reference)
- `practiceArea`
- `statusLabel` (server-provided display label)
- `submittedAt` (server timestamp)
- `legalBoundaryNotice` (server-provided; verbatim)

Explicitly **not rendered**, even if the response body includes them:
- `orgId` / tenant internals
- `events` / `payloadJson`
- AI packet content
- reviewer notes
- legal advice or legal conclusions

Regression test: attacker-controlled extra fields in the response body (e.g. `orgId: 'metro-university-INTERNAL'`, `events: [...]`, `aiPacket: 'FORBIDDEN'`) never appear in the rendered HTML.

## Legal-Boundary UX Rules

Every form load renders:
- "This form collects information for supervised human review. It is not legal advice."
- "A qualified reviewer will look at your intake before any action is taken on your behalf."
- "Please share only what you are comfortable sharing. Do not include unnecessary sensitive information."
- "You will not receive an AI-generated legal opinion from this form."

Consent gate:
- Submit button is disabled until practice area, sub-issue, summary (≥10 chars), and explicit consent checkbox are all set.
- Consent copy: "I understand this is not legal advice and my intake will be reviewed by a qualified person."

No promise of eligibility, legal outcome, legal advice, or representation.

## Idempotency Requirement

- Every submit generates a fresh `Idempotency-Key` via `createIdempotencyKey()` (Phase 2E.5 helper, uses `crypto.randomUUID()`).
- Regression test proves the header is present on every submit.
- The proxy middleware rejects submissions without the header in non-dev mode.

## Tenant Slug Routing Model

- Public URL uses `tenantSlug` (never raw `orgId`).
- Slug format validated on the server via `isValidTenantSlug` (same regex as `resolveOrgContext`).
- Unknown or malformed slug → generic "intake unavailable" state.
- The resolver never confirms tenant existence in error messages.
- The API separately re-verifies the slug on submit — no client can bypass.

## Error Handling

- `400` (validation): renders inline field-level error.
- `429` (rate limit): renders "Too many submissions. Please wait a moment and try again."
- `403`/`404`: renders generic "This intake is not available for the requested organisation." — never leaks the specific slug.
- `500`/other: renders generic "Your intake could not be submitted. Please try again later."

## Known Gaps Before Phase 2G Demo Smoke Gate

1. **Bilingual copy**: form labels, hint text, and error messages are hard-coded English. Must migrate to `next-intl` message catalogs before external stakeholder demo (both `en-CA` and `fr-CA`).
2. **Document upload**: the form does not currently support attaching documents. Legacy CourtLens had an upload step; the API and matter model already support document linkage via evidence primitives, but no UI exists. Add before pilot.
3. **Status check page**: no public UI to check the status of a previously submitted matter. Legacy `/check-status` flow is not yet rebuilt.
4. **Success page routing**: confirmation renders in-place on the intake page. Consider routing to a dedicated `/intake/confirmation` page for shareability.
5. **Analytics / abandonment tracking**: no client-side analytics yet. Do not add without an explicit privacy review.
6. **Accessibility audit**: the form uses native HTML controls and labels, but no formal a11y audit has run. Do before external demo.
7. **N+1 event replay** in queue list — unchanged from Phase 2C. Deferred.
