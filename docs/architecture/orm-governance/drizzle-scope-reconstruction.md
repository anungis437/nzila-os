# Drizzle Scope Reconstruction

**Status:** Active
**Effective:** 2026-05-09
**Authority:** [orm-authority-governance.md](./orm-authority-governance.md)

This document records the reconstruction of the Union Eyes Drizzle layer
into a governance-safe, scoped ORM responsible **only** for runtime
support tables.

---

## 1. Reason for Reconstruction

Pre-reconciliation, Drizzle had drifted to broad ownership of the
operational schema. The historical lineage at
`apps/union-eyes/db/migrations/` reflects that drift. Going forward,
Django is the canonical operational ORM (see
[django-canonical-authority-formalization.md](./django-canonical-authority-formalization.md)),
so the Drizzle surface area must be narrowed.

This phase is not a refactor. It is a **scope reduction** with a
permanent narrower boundary.

---

## 2. Allowed Scope

Drizzle is restricted to:

- cache schemas (`ue_cache.*`)
- governance runtime schemas (`ue_governance.*`)
- continuity observability schemas (`ue_continuity.*`)
- attestation / evidence support schemas (`ue_attestation.*`)
- telemetry support schemas (`ue_telemetry.*`)
- operational read-model projections that are explicitly delegated
  per a PR that updates the [canonical topology](./canonical-schema-topology.md)

---

## 3. Prohibited Scope

Drizzle MUST NOT be used to declare or migrate:

- canonical business entities (Django-owned)
- identity/auth tables
- organizations, memberships, or role tables
- grievances, claims, bargaining, billing, compliance, accounting
- any table that exists today under Django ownership

---

## 4. Concrete Implementation

| Concern                         | Pre-reconciliation                              | Post-reconciliation                              |
|---------------------------------|--------------------------------------------------|--------------------------------------------------|
| `drizzle.config.ts` `schema`    | `./db/schema/union-structure-standalone.ts`     | `./db/schema-cache/cache.ts`                     |
| `drizzle.config.ts` `out`       | `./db/migrations`                                | `./db/migrations-cache`                          |
| Active migration root           | `db/migrations/` (broad)                         | `db/migrations-cache/` (scoped)                  |
| Schema barrel                   | broad multi-file barrel                          | single intentionally-empty barrel `cache.ts`     |
| Bootstrap entrypoint            | `db:migrate` → broad replay                      | `db:bootstrap` → scoped + restore + attestation  |
| Legacy lineage                  | mixed with active                                | frozen, sentinel-protected, refused at replay    |

---

## 5. Scoped Schema Directories

The scoped Drizzle layer uses the following directory layout:

```
apps/union-eyes/db/
├── schema-cache/
│   └── cache.ts          # the only schema barrel drizzle-kit reads
├── migrations-cache/
│   ├── meta/
│   │   └── _journal.json
│   └── README.md
├── migrations/           # FROZEN — historical lineage only
│   ├── .lineage-frozen
│   └── LINEAGE-FROZEN.md
└── schema/               # legacy schema files (frozen with the lineage;
                          #   not consumed by drizzle-kit going forward)
```

---

## 6. Scoped Migration Registry

The scoped registry is `db/migrations-cache/meta/_journal.json`.
Initially `entries: []`. Every new entry is generated by
`pnpm db:generate` from the scoped barrel and is therefore guaranteed
in-scope.

---

## 7. Scoped Drizzle Ownership Contracts

Every PR that adds a table to `cache.ts` must:

1. Update [canonical-schema-topology.md](./canonical-schema-topology.md)
   with the new table's namespace.
2. Demonstrate the table is not a duplicate of a Django-owned entity.
3. Document any FK to a Django-owned entity (cascade behavior, lifecycle).
4. Include a fresh `db:bootstrap` run against a clean DB in CI.

---

## 8. Scoped Replay Guarantees

- The scoped Drizzle layer is **safe to replay against a fresh DB at
  any time**, by design, and `db:bootstrap` exercises that path.
- Any future scoped migration that breaks fresh-DB replay is a release
  blocker.
- This guarantee is the antidote to the historical lineage's broken
  fresh-replay behavior.
