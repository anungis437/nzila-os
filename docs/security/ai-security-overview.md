**Status**: Active

## 1. Purpose

This document describes the AI safety, disclosure, and audit framework applied to all AI/ML surfaces in the Union Eyes application. It covers policy enforcement, audit trail design, UX disclosure requirements, admin tooling, and QA gate enforcement.

---

## 2. AI Safety Policy Enforcement

### 2.1 `enforceAISafety` (synchronous guard)

All 23 AI/ML routes call `enforceAISafety(params)` at the top of their handler. This is a **synchronous** function imported from `@nzila/policies`.

```typescript
import { enforceAISafety } from '@nzila/policies'

// Inside route handler:
enforceAISafety({ route: '/api/analytics/insights/weekly-summary', dataClass: 'insights' })
```

`enforceAISafety` throws if the route violates any platform AI policy (e.g., missing audit logging declaration, unsupported data class). It does **not** return a value.

### 2.2 `guardAiFeature` (async feature gate)

Optional async guard for feature-flag-controlled AI surfaces:

```typescript
import { guardAiFeature } from '@/lib/ai/guard'

const block = await guardAiFeature('weekly-summary', { organizationId, userId })
if (block) return block // NextResponse with 403 + error body
```

Returns `null` if the feature is enabled for the requesting context, or a `NextResponse` block with a structured error if the feature is disabled or the caller lacks access.

## 3. Audit Trail

### 3.1 `auditAIInvocation`

Every AI route must call `auditAIInvocation` before returning a response. This is an **async** function exported from `@/lib/audit-logger`.

```typescript
import { auditAIInvocation } from '@/lib/audit-logger'

const auditRefId = await auditAIInvocation({
  userId,
  organizationId,
  origin: '/api/analytics/insights/weekly-summary',
  model: 'gpt-4',
  dataClass: 'insights',
  ipAddress: request.headers.get('x-forwarded-for') ?? undefined,
  userAgent: request.headers.get('user-agent') ?? undefined,
})
```

`auditAIInvocation` returns an `auditRefId` string (a `crypto.randomUUID()` value) that must be included in the API response `meta` object.

### 3.2 Audit Log Storage

AI invocations are stored in the `audit_security.audit_logs` table with the following structure:

| Field | Value |
|---|---|
| `action` | `'invoke'` |
| `resourceType` | `'ai-route'` |
| `resourceId` | Route path (e.g., `/api/analytics/insights/weekly-summary`) |
| `metadata.eventType` | `'ai.invocation'` |
| `metadata.model` | Model identifier (e.g., `'gpt-4'`) |
| `metadata.dataClass` | Data classification (e.g., `'insights'`, `'chat'`) |
| `metadata.auditRefId` | UUID matching the `meta.auditRefId` returned to the client |

### 3.3 Querying AI Audit Logs

```sql
SELECT * FROM audit_security.audit_logs
WHERE metadata->>'eventType' = 'ai.invocation'
ORDER BY created_at DESC;
```

The `AuditEventType.AI_INVOCATION` enum value equals `'ai.invocation'`.

### 3.4 `aiReferenceId` on Persisted Insights

AI-generated insights saved to the `insight_recommendations` table include an `ai_reference_id` column (nullable `text`) that stores the `auditRefId` returned by `auditAIInvocation`. This enables end-to-end traceability from a stored AI recommendation back to the originating audit log entry.

## 4. UX Disclosure

### 4.1 `AIBanner` Component

All UI surfaces that display AI-generated content must render the `AIBanner` component:

```tsx
import { AIBanner } from '@/components/ai'

// In page or section component:
<AIBanner />
```

**Location**: `apps/union-eyes/components/ai/AIBanner.tsx`

The banner renders a non-dismissible notice stating that the content was generated by AI and must be reviewed by a qualified human before acting on it. It is styled to be visible but non-intrusive.

### 4.2 Non-Authoritative Policy

AI-generated outputs are explicitly labelled as **advisory only**. The following `meta` fields are included on all AI route responses:

| Field | Type | Description |
|---|---|---|
| `aiGenerated` | `boolean` | Always `true` for AI routes |
| `reviewRequired` | `boolean` | `true` for background AI decisions; `false` for interactive Q&A (chatbot) |
| `source` | `string` | AI provider (e.g., `'azure-openai'`) |
| `model` | `string` | Model deployment name |
| `timestamp` | `string` | ISO 8601 timestamp of generation |
| `auditRefId` | `string` | UUID linking the response to the audit log entry |

UI surfaces must not present AI-generated content as definitive decisions or system-verified facts without an accompanying disclosure.

## 5. AI Usage Viewer (Admin)

### 5.1 Route

`GET /api/admin/ai-usage`

Returns paginated AI audit log entries from `audit_security.audit_logs` where `metadata->>'eventType' = 'ai.invocation'`. Requires `minRole: 'admin'`.

Query parameters: `page` (default 1), `limit` (default 20, max 100).

Response shape:
```json
{
  "success": true,
  "data": {
    "entries": [...],
    "total": 142,
    "page": 1,
    "limit": 20
  }
}
```

### 5.2 Admin Page

**Location**: `apps/union-eyes/app/[locale]/dashboard/admin/ai-usage/page.tsx`

Accessible at `/dashboard/admin/ai-usage`. Roles with access: `app_owner`, `cto`, `platform_lead`, `data_analytics_manager`.

Features:
- Paginated table of AI invocations (Timestamp, Origin, Model, Data Class, User ID, Org ID, Audit Ref)
- CSV export of visible entries
- Policy notice banner (non-authoritative AI advisory)

### 5.3 Sidebar Navigation

The AI Usage page is linked in the admin sidebar under the `Bot` icon with the `sidebar.aiUsage` i18n key. The nav entry is present in all 6 supported locales: `en`, `en-CA`, `fr`, `fr-CA`, `it`, `pt`.

## 6. QA Gate Enforcement

The `ue-qa-report.ts` script checks for AI compliance and adds blockers if artifacts are missing:

| Check | Blocker message if missing |
|---|---|
| `AIBanner.tsx` component exists | `'AI disclosure banner component is missing.'` |
| AI usage admin page exists | `'AI usage audit viewer page is missing.'` |

The `ue-qa-gate.ts` gate runs `ue:qa:report --enforce` and exits non-zero if any blockers are present. CI will fail if the AI disclosure or audit viewer artifacts are removed.

The QA report also tracks:
- `aiUxCoveragePercent` — coverage of AI-tagged stories
- `aiAuditCoveragePercent` — mutation story coverage for AI audit stories

## 7. Contract Tests

`apps/union-eyes/tests/api/ai-audit.spec.ts` contains 7 contract tests verifying:

1. `meta.aiGenerated = true` on AI summary routes
2. `meta.reviewRequired = true` on background AI decision routes
3. `meta.reviewRequired = false` on interactive chatbot routes
4. Audit log `eventType = 'ai.invocation'`
5. Audit log metadata includes `model` and `dataClass`
6. `auditRefId` traces from response `meta` to audit log entry
7. Churn-risk response conforms to `standardSuccessResponse` shape

## 8. Responsible AI Principles Applied

| Principle | Implementation |
|---|---|
| Transparency | `AIBanner` disclosure on all AI surfaces; `meta.aiGenerated` on all AI responses |
| Accountability | `auditAIInvocation` on every AI route; entries in `audit_security.audit_logs` |
| Human oversight | `meta.reviewRequired` flag; non-authoritative UX language |
| Access control | AI usage admin page gated by role; `enforceAISafety` on all routes |
| Traceability | `auditRefId` links API response → audit log → persisted insight |
