# Union Eyes CLC Demo Environment Realism Backlog

Purpose: Increase institutional believability of seeded demo data without introducing new system behavior.

Guardrail: This backlog is realism-only. No schema expansion, no feature expansion, no route expansion.

## Prioritization Model

P0 = Must-have before CLC demo week
P1 = Should-have if time permits
P2 = Nice-to-have post-CLC

## P0 Realism Tasks

1. Persona naming realism
- Replace any synthetic-sounding names with institutionally credible profiles.
- Ensure role-title alignment feels authentic across executive, governance, steward, member, and staff.
- Acceptance: all presenters can narrate each persona naturally in one sentence.

2. Case timeline continuity
- Verify each seeded case has chronologically coherent events.
- Remove timeline gaps that create explanation friction.
- Acceptance: no demo case requires improvisation to explain status progression.

3. Communication tone consistency
- Normalize seeded messages to institutional, calm, and respectful language.
- Remove jargon that sounds generated or overly technical.
- Acceptance: communication threads read like realistic labor relations correspondence.

4. Governance review trail plausibility
- Ensure review checkpoints and comments reflect reasonable oversight cadence.
- Prevent over-dense audit language that sounds artificial.
- Acceptance: governance walkthrough can reference review activity confidently.

5. Escalation narrative coherence
- Make escalation paths explicit in case notes where applicable.
- Ensure handoffs between roles are explainable in one breath.
- Acceptance: steward and governance demos show credible escalation discipline.

## P1 Realism Tasks

1. Onboarding examples
- Add or tune onboarding artifacts to reflect realistic first-week usage.
- Acceptance: procurement/member demos can cite practical adoption cues.

2. Case mix realism
- Balance straightforward and complex cases to avoid artificial uniformity.
- Acceptance: presenters can show both routine and high-sensitivity examples.

3. Time window authenticity
- Ensure timestamps align with a plausible operating calendar.
- Acceptance: no timestamp pattern appears fabricated during walkthrough.

## P2 Realism Tasks

1. Cross-case references
- Add light references between related cases where appropriate.
- Acceptance: continuity story improves without increasing UI complexity.

2. Longitudinal breadcrumbs
- Tune historical breadcrumbs for stronger institutional memory feel.
- Acceptance: executive narrative of continuity feels lived-in.

## Implementation Discipline

For each realism change:
- Record what changed
- Record why it improves believability
- Confirm no route/feature expansion occurred
- Validate affected demos still meet time window

## Sign-off Checklist

- Executive presenter sign-off
- Governance presenter sign-off
- Steward presenter sign-off
- Procurement presenter sign-off
- Pilot scope freeze still fully intact
