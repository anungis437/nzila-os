# Cora Domain Ownership Matrix

**Authority:** [ADR-AGRI-002](ADR/ADR-AGRI-002-cora-food-economy-ceiling.md)  
**Evidence baseline:** [Phase 0B seam audit](CORA_IMPLEMENTATION_SEAM_AUDIT.md)  
**Date:** 2026-10-07  
**Status:** Architecture only; no schema, permission, or runtime change.

This matrix defines semantic ownership and future write authority. “Current
implementation state” describes repository evidence, not product intent.
`org_id` filtering alone is not proof of product ownership, authorization, or
deployed RLS. Every future record and reference must be scoped to a
server-derived organization and purpose.

## Authority classes

- `CORA_WRITE_ALLOWED_FUTURE`: only Cora-owned records, after separate
  authorization and an audited, tenant-safe Cora service/repository exists.
- `SHARED_WRITE_VIA_SERVICE`: use the canonical shared service and its own
  authorization, consent, policy, and audit controls.
- `READ_ONLY_EXTERNAL`: governed and purpose-limited reads/references only.
- `AGRIMO_OWNED_DO_NOT_WRITE`: Agrimo-owned operational records; never
  mutate from Cora.
- `EXTERNAL_AUTHORITY_DO_NOT_WRITE`: external authority retains definition or
  decision control; Cora may adapt, map, or display authorized information.

## Resolution of Existing “Cora-writable” Table Note

The historical heading “Intelligence Tables (Cora-writable)” in
[`03-data-model.md`](03-data-model.md) is not an ownership contract and
conflicts with the Phase 0B finding. The three named shared tables have
unresolved product ownership and no current Cora app caller. This ADR and
matrix govern: no Cora writes to those tables are authorized. Resolve data
ownership, source lineage, tenancy enforcement, and grants before any future
reuse; otherwise use an additive Cora-owned domain repository.

## Implementation Preconditions

Before any `CORA_WRITE_ALLOWED_FUTURE` or `SHARED_WRITE_VIA_SERVICE` record
is implemented, a separately authorized phase must define the concrete
service permission, data purpose, consent/withdrawal, validation, audit,
evidence/provenance, retention/export, organization scope, database
roles/RLS, and denial tests. This matrix is not a schema specification and
does not authorize writes.
