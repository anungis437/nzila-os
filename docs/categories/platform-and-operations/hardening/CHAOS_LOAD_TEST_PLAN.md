## 2. Chaos Scenarios

### C1 — Database Connection Pool Exhaustion

| Property | Value |
|----------|-------|
| Target | PostgreSQL connection pool |
| Injection | Saturate pool to `max_connections`, then issue a financial write |
| Expected | Write queued or fails with retryable error; no silent data loss |
| Validation | `validateLedgerIntegrity()` passes after pool recovers |

### C2 — Storage Unavailability

| Property | Value |
|----------|-------|
| Target | Azure Blob Storage (`nzilastagingstore`) |
| Injection | Block outbound calls to storage endpoint for 30s |
| Expected | Upload/download operations fail gracefully with circuit breaker |
| Validation | Evidence uploads resume after connectivity restored |

### C3 — Clerk Authentication Outage

| Property | Value |
|----------|-------|
| Target | Clerk satellite mode (union-eyes) |
| Injection | Invalid JWKS endpoint for 60s |
| Expected | Authenticated requests return 401; no silent privilege escalation |
| Validation | Token validation resumes after JWKS endpoint recovers |

### C4 — Concurrent Payout + Dispute Filing

| Property | Value |
|----------|-------|
| Target | Economic enforcer + dispute impact |
| Injection | Issue payout and file dispute simultaneously against same entity |
| Expected | Either payout completes before freeze, or payout blocked by dispute |
| Validation | No payout executes after freeze timestamp |

### C5 — Event Settlement During Partial Refund Storm

| Property | Value |
|----------|-------|
| Target | Ticketing settlement engine |
| Injection | 100 concurrent refund requests during settlement batch |
| Expected | Settlement amount adjusts for all processed refunds; no double-count |
| Validation | `platformFees + promoter + artist = net` after settlement |

## 3. Load Test Profiles
