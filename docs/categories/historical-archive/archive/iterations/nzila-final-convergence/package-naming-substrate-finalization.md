# Package Naming & Substrate Finalization

> Finalize package-level convergence under the cognition substrate doctrine.

## 1. Convergence Statement

Package naming must converge from **AI-feature semantics** to **cognition substrate semantics** — without destabilizing imports, CI, or deployment chains.

This is **semantic infrastructure hardening**, not cosmetic renaming.

## 2. Convergence Targets

Refactor remaining:

- AI-centric package names
- assistant-centric semantics
- recommendation-centric semantics
- intelligence-platform semantics

Toward:

- cognition substrate semantics
- continuity substrate semantics
- governance substrate semantics
- operational memory semantics
- bounded interpretation semantics

## 3. Canonical Substrate Vocabulary

| Forward direction | Avoid |
|-------------------|-------|
| `*-cognition-substrate` | `ai-*` |
| `*-continuity-substrate` | `*-intelligence` (as standalone framing) |
| `*-governance-substrate` | `*-recommendation-engine` |
| `*-operational-memory` | `*-copilot` |
| `*-bounded-inference` | `*-assistant` |

## 4. Refactor Discipline

- Refactor `description` fields, README headings, public-API doc strings, internal narrative.
- Preserve package names, import specifiers, exported symbol names, and `package.json` `name` fields.
- Symbol-level renames are deferred to dedicated follow-on PRs to preserve CI stability and downstream consumer compatibility.
