# Operator Journey Consistency

> **Status:** Canonical convergence · **Layer:** Journeys · **Inherits:** [shared-role-experience-model.md](shared-role-experience-model.md)

## 1. Objective

Ensure operator journeys remain continuous as operators move between Nzila products.

## 2. Canonical journeys

| Journey | Steps |
|---|---|
| Onboarding | Doctrine read → role assignment → first calm surface |
| Governance review | Posture → continuity → review → decision |
| Rollout review | Pacing band → continuity → legitimacy → decision |
| Deployment review | Release lineage → topology → legitimacy → decision |
| Continuity review | Banding → trajectory → stabilization guidance → decision |
| Evidence review | Filtered summary → cited content hash → decision |
| Stabilization review | Banded signal → advisory → decision |
| Operational readiness review | Banded readiness → continuity → decision |

## 3. Required validation

Each journey must satisfy:

- **Transition continuity** — leaving and re-entering preserves context.
- **Navigation continuity** — the canonical sidebar shape is preserved across the journey.
- **Governance continuity** — posture readings render with the same vocabulary.
- **Cognitive continuity** — reading load stays bounded throughout.
- **Operational comprehension** — the operator can describe the journey in one sentence at the end.

## 4. Required outputs

`getCanonicalOperatorPathway()` returns the canonical pathway descriptor consumed by app journey tests and journey docs.

## 5. Discipline

A journey succeeds when an operator describes the move from one Nzila product to another as "the same institution, a different room".
