# Package Substrate Maturity Convergence

> Finalize package-level philosophical convergence under the cognition doctrine.

## 1. Convergence Statement

Package architecture must feel **institutionally intentional** — a coherent cognition substrate, not a portfolio of AI features.

## 2. Convergence Targets

- `packages/ai-core` → governance-safe cognition primitives substrate.
- `packages/ai-sdk` → bounded cognition output SDK.
- `packages/ai-registry` → cognition asset registry.
- `packages/ai-control` → cognition control / budget substrate.
- `packages/clc-executive-intelligence` → executive cognition substrate.
- `packages/clc-decision-intelligence` → decision cognition substrate.
- `packages/cfo-intelligence` → financial operational cognition substrate.
- `packages/platform-intelligence` → platform cognition aggregator.
- `packages/workload-intelligence` → workload continuity substrate.
- `packages/policy-intelligence` → policy continuity substrate.
- `packages/trustops-intelligence` → trust-ops continuity substrate.
- `packages/zonga-intelligence` → content continuity substrate.
- `packages/agri-intelligence` / `agrimo-intelligence` → domain continuity substrates.

## 3. Required Convergence Disciplines

### 3.1 Substrate Naming

Forward-direction naming prefers:

- `*-cognition-substrate`
- `*-continuity-substrate`
- `*-memory-substrate`
- `*-bounded-inference`

over:

- `ai-*`
- `*-intelligence`
- `*-recommendation-engine`
- `*-copilot`

### 3.2 Substrate Descriptions

Package `description` fields must reflect bounded cognition substrate, not AI feature framing.

### 3.3 Substrate Exports

Public APIs must:

- present bounded inference primitives
- preserve audit/escalation surfaces
- avoid surveillance-risk primitives
- avoid behavioral optimization scoring as a public primitive

## 4. Rename Strategy

Renames are intentionally deferred to follow-on PRs to preserve CI stability and downstream consumer compatibility. The doctrinal posture is enforced **first**; symbol-level renames roll in second.
