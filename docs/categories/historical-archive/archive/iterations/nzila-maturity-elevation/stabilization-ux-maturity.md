# Stabilization UX Maturity

> The ecosystem must feel **stabilizing under stress**.

## 1. Convergence Statement

Stabilization UX is the difference between an enterprise application and institutional operating infrastructure. Under stress (incidents, refusals, rollbacks, escalations), the ecosystem must remain calm, bounded, and continuity-safe.

## 2. Stabilization Targets

- Refusal UX
- Rollback UX
- Onboarding UX (under uncertainty)
- Escalation UX
- Restoration UX
- Continuity summaries
- Operational guidance under failure conditions

## 3. Stabilization UX Invariants

### 3.1 Refusal

When the system refuses an action, the surface must:

- explain the bounded reason
- expose the escalation path
- preserve the operator's authority context
- avoid blame language

### 3.2 Rollback

When the system rolls back, the surface must:

- preserve the operator's prior context
- present a continuity-safe restoration summary
- expose the human reviewer of record

### 3.3 Escalation

Every escalation surface must:

- name the next human authority
- bound the interpretive context
- present cadence-aware urgency without anxiety mechanics

### 3.4 Restoration

Restoration UX must reaffirm continuity, not re-litigate failure.

## 4. Tone Canon

- calm
- bounded
- non-blame
- continuity-restoring
- governance-readable
