# Real Operational Workflows

> **Status:** Canonical governance experience · **Layer:** Workflows · **Inherits:** [executive-governance-review-workflows.md](../nzila-governance-operations/executive-governance-review-workflows.md)

## 1. Objective

Create governance-operable workflows that produce real, append-only decisions in the `DecisionLedger`.

## 2. Required workflows

| Workflow | Decision shape |
|---|---|
| Deployment review | acknowledge / approve_with_conditions / reject |
| Continuity review | acknowledge / request_clarification |
| Governance posture review | acknowledge / approve_with_conditions |
| Pilot readiness review | approve_with_conditions / reject |
| Attestation review | acknowledge / request_clarification |
| Governance evidence review | acknowledge |
| Operational stabilization review | acknowledge / approve_with_conditions |
| Modernization pacing review | acknowledge / request_clarification |

## 3. Required characteristics

- **Sparse** — one decision per session.
- **Interpretable** — every step renders an institutional sentence.
- **Stabilization-oriented** — advisory text always recommends slowing, distributing, or extending.
- **Human-authoritative** — the system never auto-advances a decision.

## 4. Refused behaviors

- Auto-remediation.
- Governance automation overreach.
- AI replacement of governance authority.
- Operational coercion.
- Real-time pressure cues.

## 5. Discipline

A workflow succeeds when a reviewer leaves with one clear, deliberate decision recorded under doctrine. Workflows that produce many micro-decisions, or none at all, are failures of design.
