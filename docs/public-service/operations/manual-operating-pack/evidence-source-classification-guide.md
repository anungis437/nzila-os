# Evidence-Source Classification Guide

> **Internal operating template. Not public copy. Not for external use unless separately reviewed and approved.**

## 1. Purpose

Classify every source before it is used in a CLEAR/SAGE proof run, so public and administrative material is
kept distinct from authorized-only and excluded material.

## 2. Source classes

- **Public** — published, openly available material (mandate statements, public guidance, annual reports).
- **Administrative** — internal operating/process material usable with normal internal handling.
- **Authorized-only** — material usable only with explicit, recorded authorization; marked
  `[AUTHORIZED-ONLY]` and not accessed until authorized.
- **Excluded** — material that must not be registered or accessed in a proof run.
- **Unknown / needs review** — unclassified; treated as excluded until reviewed.

### Quick reference

| Class | Use allowed? | Access rule |
| --- | --- | --- |
| Public | Yes | Reference/link first |
| Administrative | Yes, with normal internal handling | Reference/link first |
| Authorized-only | Placeholder only until authorized | `[AUTHORIZED-ONLY]`; not accessed until recorded authorization |
| Excluded | No | Not registered, not accessed |
| Unknown / needs review | No until reclassified | Treat as excluded; escalate to a reviewer |

## 3. Allowed source categories

- public mandate statement
- public policy / regulatory-policy framework
- public guidance page inventory
- public complaint process guide
- public accessibility plan
- public service standards
- public modernization / digital strategy
- public annual report
- public consultation or outreach / education materials

## 4. Authorized-only source categories

- `[AUTHORIZED-ONLY]` internal owner interview notes
- `[AUTHORIZED-ONLY]` internal public-guidance update tracker

These are placeholders for workflow testing only. They do not imply access, collection, review, permission,
data extraction, or system integration until separately authorized, minimized, and demonstrated necessary.

## 5. Excluded source categories

- case files, complaint files, investigation files
- enforcement files, inspection files, licensing case files
- protected-disclosure files
- adjudicative records, evidence records, witness records
- complainant/respondent records, regulated-entity records
- draft findings, draft reasons, draft recommendations, remedy deliberations
- privileged legal advice
- personal information (unless explicitly authorized, minimized, and necessary)

## 6. Domain-specific exclusions

- **Regulator boundary** — exclude investigations, enforcement, inspections, licensing, compliance
  determinations, penalties, adjudication, complaint handling tied to enforcement, and regulated-entity
  records/outcomes (see [kit-conventions.md](../kit-conventions.md), Section 8).
- **Tribunal / ombuds boundary** — exclude complaint intake/screening, investigation, protected-disclosure
  handling, adjudication, evidence assessment, findings/reasons/recommendations/remedies, and case-outcome
  material (see [kit-conventions.md](../kit-conventions.md), Section 9).
- **Health / PHI boundary deferred** — Health-system, clinical, PHI, patient-data, and health-record
  materials remain deferred unless a separately approved Proof Run 0.4 is opened. This pack does not claim
  health-system readiness.

## 7. Personal information rule

Do not collect personal information unless explicitly authorized, minimized, and necessary. When in doubt,
classify as excluded and record the reason.

## 9. Escalation rule

Any source classed **Unknown / needs review** is treated as excluded until an internal reviewer
reclassifies it. Escalate authorized-only questions before use.

## 10. Examples

- *Public mandate statement* → Public → allowed → reference-first.
- *`[AUTHORIZED-ONLY]` internal owner interview notes* → Authorized-only → placeholder, not accessed.
- *Complaint file* → Excluded → not registered, not accessed.
- *Patient record* → Excluded (health/PHI deferred) → not in scope for this pack.
