# CLEAR/SAGE Alpha Operating Kit — Operations Index

> Internal governance material. This is the manual internal workspace kit used to run the CLEAR method
> and prepare SAGE-style workspaces **before software exists**. It is not a public route, UI, product,
> demo, pricing, pilot, procurement offer, or availability claim.

## 1. Purpose

CIVIC, CLEAR, SAGE, and the Public-Institution Adaptation Framework define the architecture. This kit
turns that architecture into something we can *operate by hand* today — running CLEAR as a repeatable
method and assembling SAGE-style workspaces manually, so we can learn before any software is built.

## 2. What this kit is

- A set of internal templates for running CLEAR manually.
- A manual, document-based way to assemble a SAGE-style workspace for one institutional question.
- An internal quality gate that keeps every workspace inside the canonical boundaries.

## 3. What this kit is not

- It does not mean SAGE is launched, available, or productized.
- It does not create a product, a public offer, or a procurement-ready service.
- It does not create a public route, UI, or app copy.
- It does not change the public-facing status of SAGE.

## 4. Operating order

1. Start with the institution intake worksheet.
2. Select the institution type from the adaptation framework.
3. Record institution-specific red lines.
4. Build the evidence source register.
5. Draft the CLEAR brief.
6. Create the manual SAGE workspace summary.
7. Complete the assurance package checklist.
8. Record whether anything should be integrated into public copy, FAQ, CLEAR, SAGE, or the adaptation
   framework (via the validation feedback layer).

When completing any template, apply the shared standards in `kit-conventions.md` (disclaimer block,
status definitions, confidence levels, authorized-only marker, risk-tier phrasing).

## 5. Template map

- `kit-conventions.md` — shared status, confidence, authorized-only, risk-tier, disclaimer, and manual-sync conventions
- `institution-intake-worksheet.md` — pre-conversation / pre-analysis intake
- `evidence-source-register-template.md` — evidence provenance and source control
- `clear-brief-template.md` — CLEAR method output
- `sage-workspace-template.md` — manual internal SAGE workspace
- `assurance-package-checklist.md` — pre-export / pre-share quality gate
- `sample-public-broadcaster-workspace.md` — fictional example only
- `manual-operating-readiness-summary.md` — internal readiness summary consolidating the completed proof runs
- `manual-operating-pack/README.md` — internal operating pack for completing and controlling future manual proof runs
- `internal-doctrine-map.md` — internal lineage map connecting OCI/OCRA, CIVIC, CLEAR, SAGE, and the Manual Operating Pack

## 6. Minimum quality gate

A CLEAR/SAGE internal workspace is not complete unless:

- institution type is selected
- institution-specific red lines are recorded
- scope and exclusions are explicit
- evidence sources are registered
- source-system authority is preserved
- personal information is minimized
- confidence and uncertainty are stated
- human-review path is recorded
- prohibited conclusions are avoided
- SAGE is not described as launched, available, or productized
- required internal-use disclaimer is present where applicable

## 7. Versioning and ownership

All templates carry a template-metadata block (version, status, owner, related framework, public/
internal). The kit is owned by Nzila Ventures and versioned as v0.1 (internal operating draft). Changes
follow the validation feedback layer and the adaptation framework.

## 8. Public / internal boundary

Everything in `docs/public-service/operations/` is internal only. Nothing here is an outreach asset or
