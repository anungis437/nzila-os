# Transition handoff checklist (short template)

> Reusable. Example first case: OMHRA-style leadership transition — **not** product.  
> Complete only with **authorized** evidence; do not paste sensitive/excluded material into shared notes.

## Before day 0

- [ ] Continuity discovery questions reviewed (`continuity-discovery.md`)
- [ ] Critical services listed with owners (`knowledge-dependency-map.md`)
- [ ] Evidence sources classified (`evidence-source-classes.yaml`)
- [ ] Incoming executive grants reviewed (default deny for sensitive/excluded)
- [ ] Client succession matrix confirmed as system of record (this pack does not replace it)

## Day 0–30

- [ ] Authorized onboarding checklist shared with incoming executive
- [ ] Decision records filed for material choices (named human reviewer)
- [ ] Unresolved items assigned with owners + dates
- [ ] Institutional-context / export paths verified: restricted material not visible to incoming role

## Exit criteria (pilot)

- [ ] Incoming role can reconstruct *authorized* rationale for last key choice with provenance
- [ ] Restricted path demonstrated (denied without grant)
- [ ] Success metrics baseline recorded (`success-metrics.md`) — no invented percentages
