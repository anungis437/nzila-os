## Doctrinal Posture

This phase optimizes for **substrate hardening** — not new features, not architecture expansion, not UX expansion, not additional systems, not runtime experimentation. It is **identity, lineage, and runtime integrity hardening only**. The cadence is refinement, not accumulation. Identity hardening is also the substrate of Nzila OS's **anti-surveillance** posture: institutional identity must never be coerced into a surveillance affordance.

The runtime must no longer:

- silently collapse into ambiguity
- silently degrade into fail-open behavior
- silently default to historically accumulated organizations
- silently swallow auth, role, or org resolution failures
- silently diverge between CI and local substrate
- silently embody seeded personas as institutionally illegitimate operators

## Scope Discipline

Each document below authorizes a discrete runtime hardening PR. Implementation work happens in stacked PRs, **never bundled**. The doctrine layer establishes authority; the runtime PRs execute targeted, governance-safe refactors against that authority — with reviewer-of-record approval, evidence-anchored interpretation, and bounded synthesis as the standing institutional posture.

This layer is intentionally aligned with the established maturity, cadence, and stewardship vocabulary of the prior runtime convergence layer so that downstream runtime PRs inherit the same governance-safe cognition discipline.
