# Evidence Lifecycle Policy

> **Canonical platform documentation** for audit evidence lifecycle management.

## Overview

Nzila OS evidence lifecycle policy governs how audit artifacts are collected, stored, sealed, and
retired across the platform. All security and governance evidence generated by the platform is
treated as immutable once sealed.

## Evidence Lifecycle Stages

| Stage | Description |
|-------|-------------|
| **Collection** | Evidence is gathered from runtime events, CI gates, and audit scans |
| **Staging** | Evidence is assembled into an evidence pack per release or audit cycle |
| **Sealing** | The evidence pack is hashed and sealed with a tamper-evident signature |
| **Verification** | The seal is verified downstream before the evidence pack is consumed |
| **Retention** | Sealed evidence is retained per data-residency and compliance requirements |
| **Retirement** | Evidence is retired after the applicable retention window expires |

## Tamper-Evidence Requirements

All evidence packs MUST:
- Include a SHA-256 composite hash of all included artifacts
- Be generated and verified within the same CI pipeline execution
- Be stored in an append-only evidence store
