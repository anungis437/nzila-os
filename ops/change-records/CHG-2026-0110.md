# CHG-2026-0110 — Production RLS enforcement for 12 tables

Scope: exactly the 12 tables that failed `rls-verify.ts --mode=preflight` on production on 2026-10-05 (1155/1167).
Approver: Aubert Nungisa (platform owner, sole platform user; holds service_owner and change_manager). Window: 2026-10-05 to 2026-10-09.

Findings that shaped the change:

- `public.audit_logs` and `public.organization_users` are **non-canonical public copies**. The live tables are `audit_security.audit_logs` and `user_management.organization_users`, which are already RLS+FORCE with policies. The verifier counts the public copies because the manifest names them. They are enforced here rather than weakening the manifest or verifier.
- The five Django tables (`compliance_snapshots`, `domain_events`, `evidence_packs`, `integration_idempotency_keys`, `integration_registry`) have a uuid `org_id` and no migration enabling RLS anywhere in the repo, so the existing direct-org helper is applied by a new bounded migration.
- The five workbook tables are covered by round58 (`20260910_*`), but that is a 9,217-line migration for 795 manifest entries that also rewrites grants. Applying it would exceed this change's scope, so the same helper calls are reused in a bounded migration instead.
- Policy helpers (`ue_create_*`) already exist in production, owned by `union_eyes_migration_admin`, which is a member of `nzilaadmin` and can therefore alter all 12 tables.

## What the migration does and does not do

Does: `ENABLE` + `FORCE ROW LEVEL SECURITY` and create the runtime isolation policies plus the `union_eyes_system` policy (the doctrine's role-membership-gated system principal; the verifier requires it for these tables). Asserts geometry first and asserts all 12 afterwards, or the transaction aborts.

Does not: grant anything, create or alter roles, alter functions, touch any other table, or add any `USING (true)` policy for the runtime role. Because `union_eyes_runtime` still has no privileges on these tables, application behavior is unchanged. Whether the manifest's `requiredRuntimePrivileges` should now be granted is a separate decision.

## Production application plan

1. Merge this PR (checks green, approval).
2. Capture: SQL sha256, per-table state (the script prints BEFORE/AFTER), runtime role attributes, and the rollback point. The 12 tables are empty, so the rollback script is the rollback point; no data restore is required.
3. Apply once with `scripts/apply-prod-rls-closure-twelve-tables.ts` as `union_eyes_migration_admin` (temporary firewall rule, removed afterwards).
4. Run `rls-verify.ts --mode=preflight` against production; required 1167/1167. Verify `rolsuper=false`, `rolbypassrls=false`.
5. Record results in the PIR.
