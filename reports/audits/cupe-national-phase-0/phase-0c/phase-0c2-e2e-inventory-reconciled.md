## 1. Reconciliation method (why this replaces the "149" number)

The pre-existing inventory counted `test(...)` **invocations** in source
(149 in May 2026). That number was wrong for governance purposes for
two reasons:

1. It did not expand loop-parameterized tests. A single
   `for (const role of stakeholderRoles) test(`${role}: …`, …)` invocation
   produces N runtime test cases at execution time — not one. The most
   extreme example is
   [e2e/authenticated-role-navigation.spec.ts](apps/union-eyes/e2e/authenticated-role-navigation.spec.ts)
   which contributes **43** runtime cases from what static grep sees as
   a handful of `test(...)` calls.
2. It did not reflect §8's 11-project topology at all — every case was
   attributed to a single `chromium` project that no longer exists.

The reconciled register is generated by asking Playwright itself:

```powershell
pnpm exec playwright test --list --reporter=json
```

Playwright resolves every project's `testMatch`, walks each spec, and
emits the full per-test manifest. The output is then aggregated by
project and by file. This is the ONLY source of truth used in §9 —
grep-count numbers from earlier phases are explicitly retired.
