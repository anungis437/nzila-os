## §BR-7.1 — Scope and question under review

§8 wired 11 Playwright projects (setup + 5 personas + public + security +
bilingual-en/fr + accessibility). The 5 persona projects each load a
real `nzila_session` cookie from `playwright/.auth/<role>.json`,
generated by §7's `scripts/lifecycle/generate-auth-states.ts`. Those
files are produced by real `/api/auth/password/sign-in` POSTs (UA
`playwright-e2e-auth`), against Argon2id + real PG session writes.

The public / security / bilingual / accessibility projects, by contrast,
carry a **cold** storageState (`{ cookies: [], origins: [] }`), so any
spec inside them that calls `loginAsRole` still needs the auth-service
bypass path to produce a viable session cookie.

§8 left an inline `TODO(phase-0c2-§11)` inside
`apps/union-eyes/e2e/helpers/auth.ts::loginAsRole` because the
pre-existing `PLAYWRIGHT_TEST_AUTH=true` branch **unconditionally**
injected a synthetic `nzila_session=ue-seed-session-<userId>` cookie.
When a persona spec loaded a real storageState first, the synthetic
inject would overwrite the real cookie with a value the auth-service
does not recognise, breaking every RBAC / dashboard / organization-
members assertion that followed.

§BR-7 is a **review section** answering one question:

> Does the current `loginAsRole` implementation correctly reconcile
> the "real persona storageState" path (persona projects) with the
> "cold storageState + synthetic cookie" path (public / security /
> bilingual / accessibility)?

## §BR-7.2 — Ground-truth read

Reading `apps/union-eyes/e2e/helpers/auth.ts` at HEAD `3db1d4c77`
confirms the §11(b) fix is **already implemented in-place** — no repair
work is outstanding. The relevant block (lines 52-92) reads:

```ts
if ((process.env.PLAYWRIGHT_TEST_AUTH ?? '').toLowerCase() === 'true') {
  // Phase 0C.2 §11 — reconcile with §8 persona storageState.
  //
  // When Playwright loads a project's storageState (e.g.
  // `playwright/.auth/<role>.json`), the context already carries a real
  // `nzila_session` cookie backed by a PG session row. Injecting a
  // synthetic `nzila_session=ue-seed-session-*` on top of that would
  // overwrite the valid cookie with garbage and break every test that
  // relies on the real persona (dashboard renders, RBAC checks,
  // organization_members lookups).
  //
  // Contract:
  //   • If a real `nzila_session` cookie is present → apply ONLY
  //     org-context cookies and return; do NOT touch nzila_session.
  //   • Otherwise → keep the legacy synthetic-cookie behaviour so
  //     specs written before §8 (which never opted into storageState)
  //     continue to work.
  const existing = await page.context().cookies(cookieUrl);
  const hasRealSession = existing.some(
    (c) => c.name === 'nzila_session' && c.value.length > 0,
  );
  if (hasRealSession) {
    await page.context().addCookies(orgContextCookies);
    return;
  }
  await page.context().addCookies([
    {
      name: 'nzila_session',
      value: `ue-seed-session-${fixture.userId}`,
      url: cookieUrl,
      httpOnly: true,
      secure: false,
      sameSite: 'Lax',
    },
    ...orgContextCookies,
  ]);

  return;
}

await loginAsTestUser(page.request, fixture.email);
await page.context().addCookies(orgContextCookies);
```

The `hasRealSession` short-circuit is the reconciliation shim; the
synthetic fallback is unchanged from the §8-era code.

All 11 projects resolve into a consistent behaviour under the §11(b)
contract. No project produces the pathological outcome (synthetic
cookie overwriting a real session) that §8's TODO warned about.

Two edge cases worth naming:

1. **`storageState` file exists but is empty / corrupted.** The
   `hasRealSession` check requires `c.value.length > 0`. An empty
   `nzila_session` value is treated as "no real session", the fallback
   fires, and the spec still boots — noisy but not fatal. `auth-state.setup.ts`
   (from §8) validates the storageState before the persona projects
   depend on it, so this is defence-in-depth, not primary.

2. **`PLAYWRIGHT_TEST_AUTH` unset in a persona project.** Cannot
   happen under the governed lifecycle — `scripts/lifecycle/run.ts`
   step 10 injects `PLAYWRIGHT_TEST_AUTH=true` into `pwEnv`
   unconditionally (§8 wired this via env.ts line 165). If somebody
   invokes `pnpm exec playwright test` directly without going through
   `e2e:governed`, the persona projects would call `loginAsTestUser`
   (real HTTP) which is also correct — it just costs an extra login.

## §BR-7.4 — Regression guard

`apps/union-eyes/tests/auth-reconciliation.test.ts` — 14 static-
analysis assertions on the current source of `auth.ts`. Design mirrors
§12 / §13 / §14 / §BR-6 test-file placement (`apps/union-eyes/tests/`,
NOT `apps/union-eyes/tests/e2e/` — the latter is excluded from vitest
by `apps/union-eyes/vitest.config.ts`).

Assertions pin the following invariants:

1. `Page` and `APIRequestContext` imported as type-only from
   `@playwright/test`.
2. `loginAsRole(page: Page, role: StakeholderRole): Promise<void>`
   signature preserved.
3. `PLAYWRIGHT_TEST_AUTH` read via `process.env`, lowercased before
   comparison to `'true'`.
4. `page.context().cookies(cookieUrl)` is the sole probe for existing
   cookies (no side-channel).
5. Real-session detection uses **both** `c.name === 'nzila_session'`
   **and** `c.value.length > 0` (empty value → treated as absent).
6. Short-circuit branch: inside `if (hasRealSession)`, `addCookies` is
   called with `orgContextCookies` (never nzila_session), then `return;`.
7. Three org-selection cookies (`selected_org_id` /
   `selected_organization_id` / `selected_tenant_id`) are always
   applied.
8. `active-organization` cookie is always cleared (`expires: 0`).
9. Synthetic fallback still emits `nzila_session=ue-seed-session-${fixture.userId}`.
10. Synthetic cookie retains `httpOnly: true` and `sameSite: 'Lax'`
    (matches real cookie flags).
11. Non-bypass path (else) calls `loginAsTestUser(page.request, fixture.email)`.
12. Non-bypass path applies org-context cookies **after** the HTTP
    login (`lastIndexOf` ensures we check the trailing call, not the
    short-circuit call).
13. `Phase 0C.2 §11`, `synthetic`, and `storageState` all appear in
    the source (rationale comment survives future edits).
14. `baseUrl` sourced via `getBaseUrl()` helper, not a hardcoded URL.

Result: **14/14 pass in 10ms**. Combined with §BR-4 teardown (7) and
§BR-6 project-filter (14): **35/35 lifecycle+auth guards pass in 673ms**.
