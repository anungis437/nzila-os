# UnionEyes — Performance Baseline

> **Honest baseline, not aspirational targets.**
> Generated by: `pnpm -C apps/union-eyes perf:baseline`
> Environment: Staging (Canada Central Azure Container Apps)

## Acceptance Thresholds

| Endpoint | p95 target | Notes |
|---|---|---|
| `GET /api/health` | < 300ms | Liveness probe — must be fast |
| `GET /api/metrics/operational` | < 1s | Domain aggregate — DB query involved |
| `GET /api/governance/telemetry` | < 1.5s | Multi-table aggregate |
| `GET /api/evidence/export` | < 3s | Normal case bundle |
| `GET /api/workbench/assigned` | < 1s | Steward dashboard |
| Dashboard page load | < 2s | Seeded staging data |
| Grievance list (100 cases) | < 1.5s | Paginated |
| Grievance list (1000 cases) | < 2s | Index-dependent |
| Grievance detail + timeline | < 1.5s | With events + audit trail |
| Universal search | < 1s | Org-scoped text search |

## Benchmark Method

Run `pnpm -C apps/union-eyes perf:baseline` against a running staging instance.

The script:
1. Seeds timing from 10 warm-up requests per endpoint
2. Records p50 / p95 / p99 from 50 samples per endpoint
3. Outputs JSON results to `scripts/perf-results.json`
4. Compares against thresholds — exits non-zero on regression

## Known Characteristics

### Query patterns
- All case/claim queries are org-scoped (`WHERE org_id = $1`) — indexed
- Dashboard aggregations use materialized counts where available
- Evidence export is single-case bundle — acceptable to be slower
- Universal search uses trigram index + org filter

### Expected bottlenecks
- First-request cold start on Azure Container Apps (typically 800ms–2s)
- DB connection pool saturation under concurrent load (max 20 connections on staging)
- Evidence export with large document set (>20 documents) may approach 3s p95

### Degraded-but-acceptable scenarios
- Redis unavailable: metrics endpoint falls back to direct DB query (~+500ms)
- Auth middleware latency: auth middleware adds ~5–30ms per request (PG session lookup or NextAuth JWT verify)

## Regression Policy

Performance regressions are caught by:
1. `tooling/contract-tests/perf-budget-gate.test.ts` — checks static budgets in `nzila-truth-manifest.json`
2. Azure Monitor workbook dashboards — p95 response times per route
3. `pnpm -C apps/union-eyes perf:baseline` — pre-release manual gate

A p95 regression > 50% vs baseline blocks staging sign-off.
